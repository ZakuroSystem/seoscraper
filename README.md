# seoscraper

キーワードを指定して検索し、記事情報を取得するシンプルな CLI ツールです。
文字化け判定、本文・SEOタイトルの共通部分列分析、ログ出力機能も備えています。

## 特徴

* Google 検索から記事 URL を高速取得
* HTML を複数エンコード候補でデコードし、文字化けを自動判定
* robots.txt の有無を確認
* 公開日、SEOタイトル、本文の抜粋を取得
* **本文・SEOタイトルの共通部分列分析（共通テキストを上位表示）**
* 共通本文判定を無効化するトグルと、各ページの見出し (h1〜h6) 抽出
* ログをコンソール・ファイルに出力（ローテーション対応）
* 調査結果を CSV / JSON 形式で保存可能
* Flask を用いた HTML Web UI（ポート5007、0.0.0.0で待ち受け）に対応
* ページ別の生データはデフォルト非表示（CLIでは`--show-pages`で表示、Web UIでは折りたたみ表示）
* 出現頻度が高すぎる共通サブ文字列や検索語・短い仮名列を自動除外し分析の信頼性を向上
* 共通サブ文字列ごとの出現割合を表示し、重要度を直感的に評価可能
* tiktoken によるトークン列分析モード（デフォルト）を搭載
* Janome による形態素解析で各ページの語数と上位キーワード頻度を算出
* 編集距離に基づき類似キーワードを統合し長い語形を代表として集計（閾値指定可、デフォルト18%）
* トークンと文字列を組み合わせたハイブリッド分析で高精度な共通判定
* プロセス並列により検索と解析を高速化（`--workers` で制御、デフォルトはCPUコア数）
* 除外リストに `/正規表現/` を記述して不要なフレーズを柔軟に無視
* メタディスクリプション、画像数、リンク数をスクレイピングして表示
* ローカルまたは環境変数 `OLLAMA_API_BASE` で指定した Ollama サーバーの `gpt-oss:20b` モデルを自動検出し、利用可能なら検索結果からブログ指示書と本文を生成（見つからない場合はスキップ）
* `gpt-oss:20b` による類似キーワード10件生成ボタンを備え、各入力キーワードごとに生成した語を改行区切りで検索語欄へ追加（応答はキーワードのみ）
* 検索キーワードは改行で複数指定でき、各キーワードごとにスクレイピングを実行。類似キーワード追加も各キーワードごとに行われ、結果は改行で挿入されます
* 検索結果の取得件数は最大50件まで指定可能
* 抽出した見出しをAIに渡して、どのようなブログ記事を書くべきかをまとめた指示書を生成
* Web UI のチェックボックスで高性能AI `gpt-oss:120b` を選択可能（警告表示付き、タイムアウト690秒）。通常は `gpt-oss:20b`（タイムアウト160秒）
* 生成されたレポートとブログ記事は Markdown (`.md`) で保存され、Web UI からプレビューおよびダウンロードが可能
* ブログ生成後に「HTML化」ボタンでAIにスタイル付きHTMLへ変換し、色や太字を使った読みやすいレイアウトを確認・ダウンロードできる
* 生成されたブログをAIで評価し修正点をまとめる「生成されたブログをAIで評価」ボタンと、評価結果を反映した「ブログ修正版を作成」ボタンを備え、Markdownでのダウンロードにも対応
* Markdown プレビューは表やコードなどの拡張記法にも対応し、生成結果を完全に確認できる
* スクレイピング結果・レポート・ブログの各ファイルは自動保存され、Web UI から履歴として参照・ダウンロードできる
* Web UI は検索→レポート生成→ブログ生成の順にボタンが現れる段階的な操作で、各結果は Markdown プレビューとダウンロードリンクを提供。AI 呼び出しのログも画面に表示され、失敗時は理由も確認可能
* 検索・解析中のログはサーバーからSSEで逐次送信され、ページを再読込せず進捗と結果を確認できる
* レポート・ブログ生成中はサーバーからのトークンがリアルタイムにストリーミングされ、モデル未検出などのエラーも同じ領域に表示される
* ブログ作成時には「人間風」モードと雰囲気プリセット（ビジネス/カジュアル/フレンドリー/フォーマル）を選択でき、さらに追加指示で詳細なトーン指定が可能。追加指示には、まとめたい内容や検索ワードを選んだ理由を記入すると精度が向上
* レポート生成後は通常のブログに加え、案件や見積りへの誘導を一切含まない情報提供専用ブログもボタンひとつで生成可能
* Ollama が Web 検索拡張に対応している場合、環境変数 `OLLAMA_WEB_SEARCH=1` を設定すると検索しながら記事を生成

## インストール

Python 3.12 など互換バージョンで動作します。まず依存パッケージをインストールしてください。

```bash
pip install -r requirements.txt
```

## 使い方

基本的な実行例:

```bash
python scraper.py "openai" -n 3 --delay 1.5 --chars 500
```

* `-n` : 取得件数（デフォルト 10）
* `--delay` : 各リクエスト前の待機秒数（デフォルト 0.0）
* `--workers` : 並列リクエスト数（デフォルト CPUコア数）
* `--chars` : 本文の表示文字数（デフォルト 1000）
* `--merge-percent` : 類似キーワードを統合する最大編集距離パーセンテージ（デフォルト 18）
* `--expand-keywords` : `gpt-oss:20b` で各入力キーワードにつき関連語を10件生成し、検索語に追加
* `--log-file` : ログファイルのパスを指定するとファイル出力（省略時はコンソールのみ）
* `--log-level` : ログレベル (`DEBUG` / `INFO` / `WARNING` / `ERROR` / `CRITICAL`)
* `--results-csv` : 結果を CSV に保存
* `--results-json` : 結果とメタ情報を JSON に保存
* `--show-pages` : ページ別の生データをコンソールに表示
* `--rank-k` : 共通本文・共通タイトルの上位件数（デフォルト 15）
* `--analyze-chars` : 分析する文字数を指定 (デフォルト5000)
* `--max-common-ratio` : 共通サブ文字列とみなす最大出現率（デフォルト 0.8）
* `--analysis-mode` : 共通判定に用いる解析モード (`tiktoken` / `char` / `hybrid`、デフォルト `tiktoken`)
* `--exclude-file` : 除外文字や `/regex/` を記述したテキストファイル


### 語数・キーワード解析

Janome を用いて本文を形態素解析し、名詞のみを対象に語数と出現頻度上位のキーワードを算出します。助詞・助動詞などのストップワードは自動的に除外されます。CLI / Web UI で表示され、CSV や JSON の結果にも `word_count` と `top_keywords` フィールドとして保存されます。また、編集距離が *文字数×1.5* の閾値以下であれば長い語形に統合し、`--merge-percent` や Web UI の入力欄で割合(%)を指定できます。挿入1文字目=1.0、2文字目=1.5、3文字目以降=3.0、削除=2.0、置換=3.0 の重みで距離を計算します。

解析速度向上のため、各スレッドで Janome トークナイザーを再利用し、トークンを一時リストに貯めずに直接カウントしています。

### 追加のスクレイピング指標

各ページの meta description、画像 (`<img>`) タグ数、リンク (`<a>`) タグ数も取得します。これらは CLI / Web UI で確認でき、CSV や JSON の結果にも `description`、`images`、`links` フィールドとして保存されます。

### AIによるブログ指示書と執筆

検索結果と共通フレーズを集約し、ローカルの Ollama `gpt-oss:20b` モデルが利用可能な場合は SEO ブログ記事を書くための指示書を生成し、続けて本文も自動執筆します。接続先は環境変数 `OLLAMA_API_BASE`（デフォルト `http://localhost:11434`）で変更でき、モデル有無のチェック結果はキャッシュされます。リクエスト前に "Hello" を送ってバックエンドをウォームアップし、その後の問い合わせは通常160秒（高性能AI選択時は690秒）待機するため、長い応答でもタイムアウトしづらくなっています。生成過程はストリーミングで表示され、記事は Markdown 形式または HTML 形式で `static/blogs/` 配下に保存され Web UI からダウンロードできます。モデルが見つからない場合は自動的にスキップされます。
レポート生成後は、案件が存在しない場合に見積りや誘導を行わない情報提供専用ブログを生成するボタンも用意されており、用途に応じて2種類のブログを出し分けできます。Ollama が Web 検索拡張に対応していれば、環境変数 `OLLAMA_WEB_SEARCH=1` を設定することで、モデルが検索しながら記事を作成します。

### Web UI

HTML ベースの Web インターフェースは次のコマンドで起動できます。

```bash
python webui.py
```

ブラウザで [http://localhost:5007](http://localhost:5007) にアクセスしてください。フォームから遅延やワーカー数、解析モード、除外パターンなど主要な機能を設定できます。検索実行後の結果はフォームより上部に表示され、本文は50文字まで表示されます。クリックすると全文が展開されます。共通本文の一致率判定はデフォルトで有効ですが、チェックボックスで無効化すると解析が省略され、その代わりに各ページの見出し(h1〜h6)が結果一覧とレポート生成に利用されます。
個別ページの詳細は「ページ別の詳細を表示」をクリックすると展開されます。
まず「実行」ボタンでスクレイピングのみを行い、結果表示後に現れる「レポート作成」ボタンで分析レポートを生成します。レポート生成後は Markdown プレビューとダウンロードリンクが表示され、続けて「ブログ作成」ボタンでブログ記事を生成できます。ブログ生成後も同様にプレビューとダウンロードリンクが表示され、生成過程のログは結果の下に表示されます。ブログ作成フォームはそのまま残るため、追加指示を変えて何度でもブログを再生成できます。レポート作成とブログ作成のフォームには追加指示を入力できるテキストボックスがあり、まとめたい内容や検索ワードを選んだ理由を記入すると生成精度が向上します。
ブログ生成後は「生成されたブログをAIで評価」ボタンで修正点をまとめ、続いて「ブログ修正版を作成」ボタンで手直しした記事を再生成できます。各結果はMarkdownプレビューとダウンロードリンクで確認可能です。
検索語の横にある「類似キーワード追加」を押すと、ローカルの `gpt-oss:20b` が各入力キーワードに対して関連語を10件ずつ生成し、改行区切りで検索語欄に追加します（モデルが無ければスキップ）。検索キーワードは改行で複数入力でき、類似キーワードも同様に改行区切りで挿入されます。取得件数は最大50件まで指定可能です。
ブログ作成フォームには雰囲気を選択するプルダウンと「人間風ブログ記事モード」があり、追加指示欄には標準で「CTA（コール・トゥ・アクション）の要素を含めないようにしてください。見出しをコピーしないで、ユニークな見出しを作ってください。」が付与されます。生成したMarkdownは「HTML化」ボタンでAIにより色や太字を含むスタイル付きHTMLへ変換し、最適化されたデザインのHTMLファイルとして保存・ダウンロードできます。
レポート・ブログ生成時の内容はサーバーからリアルタイムにストリーミング表示され、高性能AI `gpt-oss:120b` を選択した場合は最大10分ほどかかる旨の警告が表示されます。
画面下部には過去に保存されたスクレイピング結果（JSON）、レポート、ブログ記事の一覧が表示され、各ファイルをダウンロードできます。

### 実行例

```bash
python scraper.py "openai" -n 3 --delay 1.5 --chars 500 \
  --log-file scrape.log --log-level INFO \
  --results-csv results.csv --results-json results.json \
  --rank-k 10 --analyze-chars 4000 --max-common-ratio 0.8
```
